# 그슨대 — Godot 흉가 탐색 프로토타입

Godot 4.7.2에서 가져오기 및 물리 이동 검사 완료. Godot 프로젝트 관리자에서 이 폴더의 `project.godot`을 가져온 후 F6 또는 F5로 실행하세요.

## 조작

- A/D 또는 ←/→: 이동
- Space: 점프 (짧게 떼면 낮은 점프)
- 방향키 또는 WASD + Shift: 상하·대각선을 포함한 8방향 대시 (무입력은 바라보는 방향)
- R: 시작 위치로 돌아가기
- F1: 충돌 바닥과 통과형 발판 표시

캐릭터는 높이 46픽셀의 임시 크기 표식입니다. 캐릭터 아트와 몹은 포함하지 않았습니다.

## 현재 구현

- 승인된 흉가 맵 시안을 2172×724 배경으로 배치
- 768×432 카메라가 임시 캐릭터를 따라 이동, 맵 경계에서 멈춤
- 앞마당 바닥, 본채 위층의 아래에서 통과 가능한 발판, 뒤뜰 계단과 신당
- 점프 입력 버퍼, 발판 끝에서의 짧은 점프 유예, 대시, 낙하 복귀
- 시작부터 오른쪽 신당까지 이동 가능성 검사

배경은 생성 이미지 한 장입니다. 타일셋·배경 레이어·문으로 전환되는 여러 방은 아직 나누지 않았습니다. 원근으로 표현된 계단과 바닥 경계는 2D 충돌 도형으로 근사했습니다. F1로 겹침을 확인하고, 이동 감각을 확정한 다음 맵을 타일로 다시 제작하는 순서가 적합합니다. 적·전투·장비는 미구현입니다.

## 검사

Godot 실행 파일로 다음 명령을 실행합니다.

```
godot --headless --path . --fixed-fps 60 --script res://tests/movement_smoke.gd
```

검사 범위: 바닥 착지, 점프 높이, 재착지, 신당까지 이동 및 맵 오른쪽 경계, 시작 위치 복귀.

## 시드 기반 랜덤 방 (현재 기본 장면)

`scenes/random_run.tscn`이 기본 시작 장면입니다. 기존 이미지 맵은 `scenes/courtyard.tscn`으로 보존했습니다.

- 전체 테스트 맵 9개를 연결하며, **맵마다 다른 방으로 가는 포탈 1~4개**를 생성합니다. 전체 맵 수는 별도 설정입니다.
- 시드에 따라 막다른 길·분기·순환 경로가 생깁니다. 문은 E로 왕복 이동합니다.
- 같은 시드와 규칙 버전이면 같은 배치입니다. 왼쪽 위 숫자 입력창으로 재현합니다.
- N: 다음 시드 / E: 문 이동·구간 출구 / R: 현재 방 시작점.
- 미니맵으로 연결 및 현재 위치를 확인할 수 있습니다.
- 방은 생성 이미지가 아닌 Godot 반복 타일·건축 모티프 초안입니다. 바닥·발판 좌표와 충돌을 공유합니다.
- 게임 창은 재실행하지 않았습니다. 현재 켜진 창은 이전 맵입니다. 다음 실행부터 랜덤 방으로 시작합니다.

검사:

```
godot --headless --path . --fixed-fps 60 --script res://tests/random_run_test.gd
```

자세한 규칙은 상위 `docs/random-room-design.md`를 참고하세요.

포탈은 양끝·상층·반대쪽 바닥으로 분산했으며, 포탈 간 최소 320픽셀 간격을 검사했습니다. 대시 검사는 `tests/dash_test.gd`로 실행합니다. 수정 사항은 다음 게임 실행부터 적용되며 현재 창은 이동/확대하지 않았습니다.

## 공통 흉가 아트 적용

랜덤 방 9종의 임시 도형을 `assets/environment/haunted-village-atlas.png`의 공통 타일·소품으로 교체했습니다. 돌바닥·흙·담장·목재 발판·창호·기와·기둥·포탈·소나무·대문·우물·신당·상자·옹기·부적·등불을 공유합니다. atlas-regions.json은 원본 시트의 투명 여백을 제외한 참조 영역이며 PNG는 수정하지 않았습니다. 먼 배경은 승인된 흉가 이미지 상단을 참조합니다.

`tests/export_art_review.gd`는 Godot의 실제 그리기 명령을 JSON으로 내보냅니다. 상위 폴더의 `room-art-preview.html`은 이를 읽는 아트 검수용 뷰어입니다. 게임 플레이 화면 자체를 캡처한 것은 아닙니다. 현재 게임 창은 재시작/이동/확대하지 않았고 변경은 다음 실행에 적용됩니다.

## 상층 동선 검사

`tests/upper_route_test.gd`는 9종 방의 시작 바닥에서 중간 발판을 거쳐 상층 포탈까지 점프만으로 도달한 뒤 하단 출구로 복귀하는 경로를 검사합니다. 봉인의 마당 상층 발판 간격을 완화했습니다. `data/enemies-proposal.json`은 몹 행동·수치 설계 제안으로 아직 게임에서 사용하지 않습니다.

## 도깨비상인

기본 시작은 `scenes/village.tscn`입니다. 마을 상인은 1~2단계 상품 4개를 프로그램 접속마다 추첨합니다. E로 거래하고 마을 오른쪽에서 E로 1층에 진입합니다. 각 층에는 평화 상점 방 1개가 있으며 높은 층에서 상위 등급 상품 확률이 증가합니다. 재고와 품절은 같은 층 왕복 중 유지합니다.

상점 구매는 런타임 재화·가방 데이터에 연결했지만 적 드롭·장비 효과·가방 화면·세이브는 아직 미구현입니다. 처음 재화는 0이며 임의 지급하지 않았습니다. 상인 외형은 임시 표식입니다. 자세한 규칙/미확정 확률은 `docs/goblin-merchant.md`, 검사는 `tests/merchant_test.gd`입니다.

## 전투·장비 프로토타입

좌클릭/J 기본 공격, 마우스 조준, Q 심장, F/G 무기 스킬, Tab/I 가방, F8 개발용 보스전 바로가기. 초기 채찍과 교체용 저등급 장비를 제공하며 재화는 0으로 시작합니다.

무사·도사·1.5배 선봉대장, HP/피격/사망, 장비 교체·양손·4악세서리, 자동 드롭 획득, 클리어 상자와 상점 구매가 연결되었습니다. 장비 고유 동작은 공유 기능으로 근사한 초기 버전이며 모든 연출/세트가 완성된 것은 아닙니다. 앱 종료 후 저장은 없습니다. 자세한 구현 범위와 조작은 `docs/combat-prototype.md`를 참고하세요.

검사: `tests/combat_test.gd`, `tests/combat_live_test.gd`. 기존 동선 검사는 `combat_enabled=false`로 적 없이 검증합니다. 현재 실행 중인 창은 건드리지 않았습니다.
