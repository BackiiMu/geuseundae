인벤토리 · JSON 레이아웃 시안

지금은 인벤토리 위치와 크기가 combat_director.gd의 숫자와 그리기 코드에 박혀 있습니다. 이 시안은 그것을 배치 정의 JSON(docs/ui/inventory-layout.json)으로 옮기고, 화면 비율마다 다른 배치(profile)를 고르는 방식입니다. 이미지는 9패치 틀·슬롯·아이콘 부품만 쓰고 한 장짜리 그림은 쓰지 않습니다. 아래 화면은 모두 그 JSON을 읽어 그린 것이고, 아래 편집 칸의 JSON을 고치면 바로 반영됩니다. 게임에는 아직 적용하지 않았습니다.

1. 화면별 미리보기

기기를 바꿔 보세요. 화면 비율에 맞는 profile이 자동으로 골라지고, 폰 노치 같은 안전 영역은 피해서 배치됩니다. 가방 칸을 눌러 선택할 수 있습니다.

2. 세 가지 배치 한눈에

같은 JSON에서 가로·정사각·세로 profile이 어떻게 달라지는지입니다. (위의 악세사리·가방 설정이 함께 적용됩니다.)

3. 배치 JSON (편집하면 위 화면이 바뀝니다)

예: bag_grid의 columns를 5로 바꾸거나 detail_name의 size를 키워 보세요. 구조는 Godot의 Control 배치(anchor·offset·rect)와 1:1로 옮길 수 있게 잡았습니다.

4. JSON 구조 설명

키역할
skins9패치 이미지 부품. slice = [위,오른쪽,아래,왼쪽] 늘어나지 않는 가장자리(Godot StyleBoxTexture margin과 같음), tint = 어둡게 섞는 색.
colors글자 색 이름표. 노드는 "color":"souls"처럼 이름으로 부른다.
profiles화면 비율별 배치. design = 기준 해상도, when = 적용할 가로/세로 비율 범위, patch = 기본 배치(root)에서 바꿀 노드만 덮어쓰기.
root.children화면 요소 목록. type: panel · label · button · slot · slotRow(악세사리 줄) · grid(가방) · slotIcon · image · rect · group.
rect / anchorrect=[x,y,w,h] 부모 기준. anchor=[0,0,1,1]은 안전 영역 전체(어둡게 덮는 판).
bind · {…} · when게임 데이터 연결(bag, accessories, selected), 글자 속 {souls} 치환, 조건부 표시(hasSelection, emptyBag).
action버튼이 보낼 이벤트 이름(inventory.equip 등). 로직은 코드가 맡고 JSON은 배치만 맡는다.

정리: 새 화면 비율이나 칸 수를 늘릴 때 코드를 고치지 않고 JSON만 고치고, 이미지를 새로 그릴 필요 없이 9패치 부품이 늘어나는 구조입니다.
