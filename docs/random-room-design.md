# 흉가 — 시드 기반 맵 연결 V5

## 사용자 확정 방향

한 맵에서 다른 방으로 이동하는 포탈이 최소 1개, 최대 4개 생성된다. **전체 맵 수를 1~4개로 제한하는 뜻이 아니다.** 시드 기반 생성을 사용한다.

- 같은 시드 + 생성 규칙 버전 + Godot 버전이면 같은 맵 연결과 장식이 나온다.
- 현재 테스트 묶음은 맵 9개이며, 전체 맵 수는 별도 설정이다. `generate(seed, room_count)`로 변경한다.
- 각 맵은 한 화면보다 넓고 높고, 카메라가 내부를 따라간다.
- 격자 위에서 연결된 방을 확장하고 인접한 방끼리 일부 순환 경로를 추가한다.
- 각 맵은 인접한 네 방향에 하나씩, 이동 포탈 1~4개를 갖는다. 막다른 방·통로·갈림길·네 갈래가 모두 가능하다.
- 포탈은 왕복 연결된다. 왼쪽·오른쪽 맵 연결은 양끝, 위쪽 맵 연결은 도달 가능한 상층 발판, 아래쪽 맵 연결은 반대쪽 바닥에 둔다. 200개 시드에서 포탈 간 최소 320픽셀 간격을 검사했다.
- 가장 먼 말단 방에 구간 완료용 출구 표식을 둔다. 이 표식은 다른 방으로 이동하는 포탈 수와 별개다.
- 1개뿐인 맵에는 다른 방 포탈을 만들 수 없으므로 테스트 묶음은 최소 2개 맵으로 생성한다.

## 후보 9종

무너진 대문 / 흉가 앞마당 / 마른 우물터 / 빈 행랑채 / 끊어진 회랑 / 결계 숲길 / 봉인된 창고 / 오래된 신당 / 봉인의 마당.

Godot 반복 타일·건축 모티프 초안이며, 바닥과 발판의 그리기와 충돌이 같은 좌표를 공유한다. 정식 아트는 후속 제작한다.

## 조작과 재현

A/D·방향키 이동 / Space 점프 / 방향키+Shift 8방향 대시 / E 문·출구 / R 현재 방 시작점 / N 다음 시드 / F1 충돌 표시.

왼쪽 위 숫자 입력창에 시드를 넣고 Enter 또는 ‘배치 생성’을 누르면 재현한다. 입력창에 집중한 동안 이동을 멈춘다. 작은 연결 지도에 현재 방과 방문 여부를 표시한다.

현재 생성 규칙 버전 5, Godot 4.7.2. 규칙·난수 호출·엔진 구현이 달라지면 같은 시드의 결과가 달라질 수 있다. 정식 저장에는 시드, 규칙 버전과 생성된 방 목록을 함께 기록해야 한다.

## 검증

200개 시드에서 전체 연결·양방향 링크·맵당 1~4개 이동 포탈·시드 재현·격자 중복 없음 검사. 9종 맵의 실제 이동 및 출구 상호작용과 20개 시드의 왕복 포탈 착지 검사. 캐릭터/몹/전투 및 윗길 전체 조합 검증은 아직 범위 밖이다.

현재 작은 게임 창은 재실행하거나 옮기지 않았다. 다음 실행의 기본 크기는 640×360이다.

## 8방향 대시

W/S 또는 ↑/↓와 A/D 또는 ←/→ 조합으로 Shift 대시 방향을 정한다. 입력이 없으면 바라보는 방향으로 대시한다. 대시 시작 시 방향을 고정하며 대각선도 속도 680을 유지한다. 기존 지속시간 0.12초, 재사용 간격 0.65초와 이동·점프 수치는 유지했다. 8방향과 무입력 방향 테스트를 통과했다.

## 상층 동선 검수 — V4

기존 플레이어 이동속도·점프 수치를 유지하고 9종 모두 시작 바닥 → 중간 발판 → 상층 포탈 → 하단 우측 출구를 실제 물리 프레임으로 검사했다. 대시는 사용하지 않았다. 봉인의 마당 상층 발판을 x752에서 x704로 48픽셀 당겨 접근 간격을 208에서 160픽셀로 줄였다. 검사 스크립트는 `godot/tests/upper_route_test.gd`. 자동 경로 검수이며 사람의 플레이 쾌적성 평가와는 구분한다.

## V5 상점 배치

각 층의 연결된 맵 중 하나를 평화 상점으로 지정한다. 방 그래프 난수와 분리한 시드 흐름을 사용한다. 마을 상점은 별도 접속 세션 재고를 사용한다. 상세 내용은 `goblin-merchant.md` 참고.
